# Messages for community-maintained repositories

Many package repositories only accept packages from their own maintainers. When sys1 isn't in one yet, we open an issue labelled `distribution`, then reach out *the way that community asks*, using [`request-template.md`](request-template.md) and filling in the blanks.

Be polite, be brief, never spam: one message per repository, through its official channel, and only after a tagged release exists.

| Repository | Where to ask |
|---|---|
| nixpkgs | GitHub issue with the "Packaging request" template at NixOS/nixpkgs |
| Guix | guix-devel mailing list or Codeberg issue tracker |
| Gentoo (Portage) | Gentoo GURU overlay, or bugs.gentoo.org "New ebuild" |
| Void (XBPS) | void-linux/void-packages GitHub, "New package" request issue |
| Alpine (apk-tools) | gitlab.alpinelinux.org aports, testing/ merge request or issue |
| Arch (official) | after AUR traction, a Trusted User may adopt it |
| Manjaro (pamac) | follows Arch/AUR |
| Slackware | SlackBuilds.org submission (we can write the SlackBuild ourselves) |
| Zenwalk (netpkg) | Zenwalk forum |
| Sabayon (Entropy) | project is legacy; ask on its community channel if active |
| FreeBSD ports | bugs.freebsd.org "New port" PR (we can write the port ourselves) |
| pkgsrc | pkgsrc-wip (we can submit to wip ourselves) |
| MacPorts | macports/macports-ports GitHub, or Trac "submission" ticket |
| Fink | fink/fink-distributions GitHub |
| Cygwin | cygwin-apps mailing list, "ITP" (intent to package) |
| F-Droid | fdroiddata merge request, after the Android app exists |
| Flathub | flathub/flathub GitHub new-app pull request (their process, not ours) |
